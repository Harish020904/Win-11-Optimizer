 you’re about to strip the junk, not torch the OS. Keep your backups ready. 🔥😏

# Ultimate (aggressive but still *safe*) debloat — surgical, reversible, production-aware

This level moves past “remove the annoying UI stuff” into **system architect territory**: block telemetry at the policy/firewall layer, un-provision inbox apps for all users, disable a larger set of nonessential services and scheduled tasks, tune Defender instead of killing it, and remove OEM cruft. **We do not delete the servicing stack, Windows Update core, Windows Security, or necessary runtimes.** If you accept those rules, proceed.

I’ll give: rationale + exact commands (PowerShell/GP/Firewall) + clear rollback notes. Apply one class at a time, reboot, test 48–72 hours, then continue.

> Quick citations for the heavy claims below: community debloat tooling and scripted approaches (Sycnex / Windows10Debloater), built-in policy options for app removal, host-file pitfalls, and safer firewall/WFP approaches. ([GitHub][1])

---

## Prep (non-negotiable)

1. Create a full disk image (Macrium, Clonezilla, or vendor tool).
2. Create a System Restore point:

   ```powershell
   Enable-ComputerRestore -Drive "C:\"
   Checkpoint-Computer -Description "pre-ultimate-debloat" -RestorePointType MODIFY_SETTINGS
   ```
3. Make Windows install media or ensure you have a recovery USB.
4. Have a separate admin user (local) available for recovery.
5. Make a plaintext rollback snippet file with the inverse commands you’re about to run.

---

## Strategy summary (what “ultimate” does)

1. **Policy + registry** hardening of telemetry (non-destructive).
2. **Firewall / WFP app-level blocking** for telemetry endpoints (safer than hosts hacks). ([Privacy Guides Community][2])
3. **Un-provision Appx packages for ALL users** (not just current user) — removes inbox UWP apps but leaves core Store runtime if you choose. Use policy where possible. ([Microsoft Support][3])
4. **Service lockdown**: move nonessential services to Manual or Disabled after observation.
5. **Scheduled task purge** of telemetry/one-time vendor jobs.
6. **Defender tuning**: exclusions for datasets/dev and selective real-time policy adjustments (don’t disable Defender).
7. **OEM cleanup** and driver management (remove vendor bloat apps, keep drivers).
8. **UI / background** finish: telemetry UI components, Spotlight, Suggestions, Widgets permanently blocked.
9. **Optional: Hibernation off & pagefile adjustments** (saves space; minor functional tradeoffs).
10. **Audit & monitoring**: list what changed and how to revert.

## Concrete steps & commands (run piece-by-piece, **read before running**)

### A — Stronger telemetry policy (works on Pro/Home via registry)

```powershell
# set telemetry to minimal (0/1 depending on SKU availability)
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DataCollection" -Force
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DataCollection" -Name "AllowTelemetry" -Type DWord -Value 0 -Force

# disable linked experiences and advertising ID
New-Item -Path "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\AdvertisingInfo" -Force
Set-ItemProperty -Path "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\AdvertisingInfo" -Name "Enabled" -Type DWord -Value 0 -Force
```

**Rollback:** delete those registry keys or reset `AllowTelemetry` to `1`/`2` depending on your SKU.

> Why policy+registry? It’s resilient across reboots and is reversible — unlike deleting files. (See community tooling & Microsoft guidance.) ([GitHub][1])

---

### B — Block telemetry *safely* with WFP/Walled-garden firewall (recommended)

**Don’t** rely on hosts file alone (can be bypassed or flagged); use an app-level WFP firewall (simplewall) or create outbound firewall rules for Edge/Telemetry services and block known telemetry domains with a managed list. Example using Windows Firewall to block a domain-resolved IP (less ideal than WFP):

```powershell
# Example: block outbound to a known telemetry IP (replace with validated IPs)
New-NetFirewallRule -DisplayName "Block MS Telemetry Example" -Direction Outbound -RemoteAddress "13.107.6.157" -Action Block -Profile Any
```

Better: install and use a small WFP GUI like **simplewall** to deny all outbound by default and whitelist; this gives total control without host file war. Privacy-guides and community discussions recommend WFP-based solutions for reliability. ([Privacy Guides Community][2])

**Rollback:** remove the firewall rule:

```powershell
Remove-NetFirewallRule -DisplayName "Block MS Telemetry Example"
```

---

### C — Remove / un-provision inbox Appx packages for *all users* (aggressive)

**Preview first.** Do **not** remove `Microsoft.WindowsStore` unless you know how to restore it.

```powershell
# List provisioned packages (preview)
Get-AppxProvisionedPackage -Online | Select DisplayName, PackageName

# Example: remove a set of consumer inbox apps (adjust list to taste)
$blacklist = @(
 "Microsoft3DBuilder",
 "Microsoft.MicrosoftSolitaireCollection",
 "Microsoft.GetHelp",
 "Microsoft.MixedReality.Portal",
 "Microsoft.MicrosoftStickyNotes",
 "Microsoft.XboxGamingOverlay",
 "Microsoft.Xbox.TCUI",
 "Microsoft.XboxGameOverlay"
)

Get-AppxProvisionedPackage -Online | Where-Object { $blacklist -contains $_.DisplayName } | ForEach-Object {
  Remove-AppxProvisionedPackage -Online -PackageName $_.PackageName
}
```

**Notes & warnings:** removing provisioned packages prevents them provisioning for new user accounts. Installed copies for existing users should be removed separately (`Get-AppxPackage -AllUsers | Remove-AppxPackage`). Reinstalling some packages later may be nontrivial without Store or PowerShell re-registration. Use Microsoft’s policy-based removal for managed environments if available. ([Microsoft Support][3])

**Rollback (if you removed something you need):** re-provisioning is cumbersome; easiest is to re-register the package or use a fresh image / Install Media to restore or run the re-install commands from a reference image. Keep a note of removed package names.

---

### D — Larger service lockdown (aggressive list; **test** before disabling)

**Principle:** set to `Manual` first. After 48–72 hours of normal operation, set to `Disabled` if safe.

Suggested services to inspect (very aggressive; skip any you use):

```
WSearch (if you never use Windows Search)
SysMain (if on SSD and noticing high I/O)
DiagTrack / CDPUserSvc / dmwappushservice
XblAuthManager, XblGameSave, XboxNetApiSvc, GamingServices
WaaSMedicSvc (Windows Update Medic — do NOT disable unless you control updates)
MapsBroker, OneSyncSvc, RetailDemo, WaaSMedicSvc (caution)
```

Example script to set Manual after preview:

```powershell
$svc = @("XblAuthManager","XblGameSave","XboxNetApiSvc","GamingServices")
foreach ($s in $svc) {
  if (Get-Service -Name $s -ErrorAction SilentlyContinue) {
    Set-Service -Name $s -StartupType Manual
    Stop-Service -Name $s -Force -ErrorAction SilentlyContinue
  }
}
```

**Rollback:** `Set-Service -Name <svc> -StartupType Automatic` and `Start-Service`.

---

### E — Scheduled tasks purge (target telemetry/telemetry-adjacent)

Preview tasks and disable ones from `Microsoft\Windows\Application Experience`, `Customer Experience Improvement Program`, and vendor-specific telemetry tasks.

```powershell
# Preview
Get-ScheduledTask | Where-Object { $_.TaskPath -match "Customer Experience|Application Experience|Maps" } | Select TaskName,TaskPath

# Example disable (do this AFTER preview)
Disable-ScheduledTask -TaskPath "\Microsoft\Windows\Application Experience\" -TaskName "ProgramDataUpdater" -ErrorAction SilentlyContinue
```

**Rollback:** `Enable-ScheduledTask`.

---

### F — Defender tuning (don’t kill it — tune it)

Add exclusions for your datasets, VMs, and development folders to avoid constant scanning:

```powershell
Add-MpPreference -ExclusionPath "D:\datasets","D:\VMs","C:\Users\Harish\Projects\node_modules"
Add-MpPreference -ExclusionProcess "C:\Program Files\VMWare\vmware.exe"
```

Consider using Defender in **Audit mode** for new rules, then move to full protection. This keeps AV while reducing noise and CPU/disk impact.

---

### G — OEM bloat & driver control

Uninstall OEM apps (Acer bloat) via `Apps & Features` or PowerShell but **keep drivers and control panel utilities you rely on** (touchpad gestures, power). If you remove essential vendor power utilities, you may lose battery optimizations.

To prevent Windows Update from auto-installing drivers:

* Group Policy: Computer Configuration → Administrative Templates → Windows Components → Windows Update → Do not include drivers with Windows Updates → **Enabled**.

---

### H — Space & performance: hibernation / pagefile choices

* Disable hibernation (frees ~hiberfile size): `powercfg -h off` (loses hibernate + Fast Startup).
* Move pagefile to secondary drive or set fixed size if you have plenty RAM. **Do not** delete pagefile entirely on systems with limited RAM.


## Rollback plan (you must save this before doing anything)

1. System Restore or disk-image restore = full recovery.
2. Re-enable services via `Set-Service -Name <svc> -StartupType Automatic`.
3. Recreate provisioned packages by re-registering or reinstalling from Store / install media. (Hard; plan ahead.)
4. Remove firewall rules with `Remove-NetFirewallRule`.
5. Re-enable scheduled tasks with `Enable-ScheduledTask`.

---

## Final cautions & community notes

* Hosts-file blocking of Microsoft telemetry is a blunt tool and has been known to trigger Defender or be bypassed. Prefer WFP/app-level blocking or policy controls where possible. ([Gist][4])
* Heavy removal of Appx packages can make re-provisioning for new system users harder. For managed fleets, Microsoft’s policy-based app removal is the safer enterprise path. ([Microsoft Support][3])
* Many community debloat scripts exist (Sycnex, Windows10Debloater); they’re convenient but treat them as templates — read and **audit every command** before running. ([GitHub][1])

# 1. Telemetry Policy Hardening

## Component modified

```text
Windows Telemetry Framework
(DataCollection policies + Advertising ID)
```

## Command executed

```powershell
New-Item -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DataCollection" -Force
Set-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DataCollection" -Name "AllowTelemetry" -Type DWord -Value 0 -Force

New-Item -Path "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\AdvertisingInfo" -Force
Set-ItemProperty -Path "HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\AdvertisingInfo" -Name "Enabled" -Type DWord -Value 0 -Force
```

## What it disables

```text
Microsoft telemetry reporting
Advertising ID tracking
Usage analytics
Activity-based personalization
```

## Drawbacks

* Microsoft support cannot access telemetry logs easily.
* Insider Preview builds may fail to install.
* Some troubleshooting tools rely on telemetry diagnostics.

## Reversible

Yes.

## Recovery

Delete the registry keys or reset values.

```powershell
Remove-Item "HKLM:\SOFTWARE\Policies\Microsoft\Windows\DataCollection"
Set-ItemProperty HKCU:\SOFTWARE\Microsoft\Windows\CurrentVersion\AdvertisingInfo Enabled 1
```
